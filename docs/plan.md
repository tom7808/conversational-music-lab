# 会話で音楽を学ぶ実験室｜企画書（ドラフト）

「会話で音楽を学ぶ実験室」は、ブラウザでリズムを聴き比べ、自分で変え、AIとの会話で理解を深める音楽学習Webアプリの企画である。初期段階では、リズムの比較・編集・再生と、その変化を説明する対話に絞って試作する。

本プロジェクトでは収益化を行わない。本物のSIWCと利用者本人のChatGPTプランによる推論、複数利用者の分離を実際に学習・検証し、非収益化のWebアプリを公開することを目的とする。OpenAIへ必要な利用申請を行う方針は決定済みである。申請対象は、複数の利用者がそれぞれのChatGPTアカウントで使うホスト型Webアプリに決定済みである。ホスト型の適用条件と承認取得は未確認である。

## 想定利用者と学習の狙い
音楽に興味がある初心者を対象にする。文章で説明を読んでも、音の位置を変えると何が違って聴こえるのか、実感しにくい場面を想定している。
このアプリでは「聴く → 変える → 質問する → もう一度聴く」を繰り返せるようにする。自分の操作と音の変化を結びつけることで理解を助ける、という仮説を検証する。需要や学習効果は今後確かめる。

## 最初に提供する体験
1. 拍に沿ったリズムと、音を鳴らす位置をずらしたリズムを聴き比べる。
2. グリッド上で音を置く位置を変え、再生する。
3. 「どこを変えた？」「なぜ違って聴こえる？」とAIに質問する。
4. 現在のパターンに沿った説明を受け、再び編集して耳で確かめる。
画面は16ステップ・ドラム3トラックを初期案とし、詳細は試作前に決める。初期範囲はリズム学習に絞る。

## 必須要件
AIとの対話には、ChatGPTアカウントで認証する仕組みであるSign in with ChatGPT（以下、SIWC）を使う。単にログインできるだけでなく、利用者が許可した本人のChatGPTプランで実際のモデル応答を得ることを必須とする。[公式導入例](https://developers.openai.com/cookbook/articles/sign-in-with-chatgpt)
また、複数の利用者が使っても、認証情報・ログイン状態・会話・リズムのパターンが他の利用者と混ざらないことを要件とする。音楽学習の体験を試すと同時に、開発者がSIWCによる認証・モデル呼び出し・利用者ごとの分離を実動作で学ぶことも、試作の目的である。

## 技術構成案と開発環境
ブラウザ側で編集画面と音声再生を扱い、バックエンド側で認証とモデル呼び出しを扱う構成を検討する。AIは定義済みの形式でパターンデータと説明を返し、データの範囲を検証して再生に反映する。任意のコードを実行させる方式は初期案に含めない。
作業・開発スペースはCodexクラウドに決定している。初回のSIWC実認証試験は、macOS のローカル環境で、同一 PC 上のブラウザ＋ローカルバックエンドを計画上採用済みである。[試験計画](auth-test-plan.md)に記録した。実装・起動・設定変更・ログイン・認証情報取得は未実施である。ローカル環境は事前検証用に限る。本番の具体的なホスト先、技術スタックと配備方式、ホスト型マルチユーザー構成の条件・承認は別途検討する。

## SIWCの利用条件と確認事項
2026年10月10日に公式資料の調査を行い、[確認できた仕様・解釈・問い合わせ事項](siwc-research.md)を記録した。調査記録の作成は完了したが、共有バックエンドの利用承認や実動作検証は未完了である。
公式資料では、ローカルで動く個人プロジェクトやオープンソースのアプリで、利用者のChatGPTプランを使う経路が案内されている。複数アカウントの登録・切り替えも説明されているが、それだけで、申請対象のホスト型Webアプリに複数の独立利用者がそれぞれのChatGPTアカウントで接続する構成が認められるとは判断できない。[プラン利用の概要](https://developers.openai.com/siwc/token-sharing-open-source)／[アカウント管理](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions)
有料またはリモートホスト型のアプリでChatGPTプランを利用する場合、公式は[問い合わせフォーム](https://openai.com/form/sign-in-with-chatgpt-interest/)を案内している。本プロジェクトは非収益化とするが、それだけで利用条件への適合を断定しない。決定済みのホスト型Webアプリと複数利用者の扱いについて、適用条件を確認してOpenAIへ必要な利用申請を行う。公式DevKitのライセンスとSIWCの利用許可は別に確認する。
OSS向けの動的登録はHTTPの127.0.0.1へのcallbackを要求する。自己所有VMの公式手順はあるが、独立した複数利用者を受け入れる共有ホスト型Webアプリの許可とは区別する。初回試験環境はこの戻り先を前提にmacOS のローカル環境へ選定済みだが、実認証での確認は未実施である。[登録仕様](https://developers.openai.com/siwc/token-sharing-open-source/sign-in)／[VMの仕様](https://developers.openai.com/siwc/token-sharing-open-source/self-hosted-vms)
将来はChatGPT内で使う公開プラグインも検討する。ただし、プラグイン内のSIWCは選定された商用パートナー向けの限定試験であり、プラグイン公開とSIWC利用の承認は別に確認する。承認を前提とした開発計画にはしない。[プラグイン内のSIWC](https://developers.openai.com/siwc/chatgpt-plugin)

## 試作の検証と完了条件
- 実際のSIWCログインから、本人のChatGPTプランによるモデル応答まで確認できる。
- リズムの比較・編集・再生ができ、AIの説明が現在のパターンに対応している。
- 利用条件に適合する構成で、協力者の同意を得た複数の実アカウントを使い、利用者・データ・ログイン状態の分離を確認できる。
- ログアウト、認証切れ、再認証時の挙動を確認できる。
模擬応答や仮の認証は開発補助に使えるが、実認証・実推論の代わりにはしない。複数アカウントでの検証が未実施なら、複数利用者対応は未完了とする。学習面では、聴き比べと対話が理解に役立つかを別途検証する。
